# Corte email pulso

Use this when compiling a daily pulse from Gmail: paid sales, free downloads, and Luma event registrations. Worker brief a human might reread.

Family, not a stencil. Vary the beat. Standard: emoji to skim, bullets, short subheads, dense. One real link per item. n/d if missing. No code fences. Silence if nothing moved. Staff → GM room, never Ignacio. Sign each finding with @YourName. Align with Formato hallazgo.

## Sources (Gmail only)

Do not connect Stripe. Look up Gmail search/get tools each run.

Paid sales:
- from:gumroad.com subject:"New sale"
- Stripe receipts that are sales to the seller, never charges the user paid as a customer

Downloads (not money):
- from:gumroad.com subject:"New download"
- Count messages in the window (a thread can hold several). $0 / test still counts as a download.

Luma inscritos:
- from:luma-mail.com (subject:"New registration" OR subject:"Invite accepted")
- Count new registrations in the window by event
- If the body has registration count so far: N going, keep the latest N per event
- Declines are not inscritos
- Event RSVPs from email, not calendar followers

Window: since the last corte (memory/ledger). User's timezone. Paginate; resultCountEstimate is threads, not a total to quote.

## Worker (short)

One finding, a few lines. Typical shape, not mandatory:

@YourName
🎯 oferta (marca, producto, $X, canal, fecha)
🔗 un link (store o evento; n/d si no hay)
⭐ score 1–5 (solo plata; volumen: n/d)
➡️ next (no A3)

Bullets and a short subhead are fine. Several findings = several tiny blocks, not a novel.

Downloads and Luma are volume, never added into $.

Score (paid only): 1 = under $5 one-off; 2 = under $10 or repeat cheap Discover; 3 = $10–29 or new channel; 4 = $30+ or material affiliate; 5 = high-ticket / LTD.

## Rules

- No names, emails, WhatsApp, DNI
- Don't invent going-count or $
- Silence if nothing moved vs last corte
